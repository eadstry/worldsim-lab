# OpenArm 24 环境能力实验

用户指定 OpenArm 方块拾放，后续生成与策略评测固定为 24 个并行环境，承接已经完成的速度实验。本目录固定实验范围并检查现有生产路径的资源准入；**没有实现新的生成或训练运行器，没有完成 24 环境运行验证**。

## 固定生产条件

三路 640×480 uint8 RGB、30 Hz 控制、60 步末尾保持、gzip2、现有 cuRobo v1 和 auto 导出。各组使用同一源示范、机器人与物理参数；完整保留失败，不以成功目标补样，不降低并行数、相机数量、分辨率或频率。正式组采用固定尝试数，必须核验实际初态配对，不能只比较 seed 标签。

先完成独立的 24 环境完整生产准入：24 次尝试、导出关闭、计数、文件回读与严格终态检查。任务失败保留在分母中，不要求所有任务都成功。软件错误、OOM 和分片丢失属于基础设施失败，停止后续正式组。资源预检通过不代表这项运行验收通过。

前两项能力实验连同准入共 600 次尝试；这只是预注册的计划数量，不是已有数据。后续方法对照与训练尚无冻结预算和可执行接口，不自动启动。原先 Franka 避障和香蕉力感知属于另一机器人任务，不能直接并入本次 OpenArm 主线；后续 OpenArm 避障、数据量和观测消融需要各自的接口与正式协议。

## 资源准入

继承已使用的保守公式：`12 + 24×4.5 + 16 + 8 = 144 GiB` **有效可用**内存，分别覆盖基础进程、在途 recorder、异步队列及余量。这是现有代码路径的准入估算，不是实测最低内存，也不证明任何形式的 24 环境实现都不可行。仅减少 writer 数不能消除 24 个同时记录的完整 RGB episode 内存。

```bash
python3 workspace-overlays/openarm-capability24/preflight.py --output runs/capability24-preflight-NEW
python3 -B -m unittest discover -s workspace-overlays/openarm-capability24 -v
```

预检只读 RAM/cgroup、GPU 设备与 compute 进程，将回执写入新目录；不启动仿真。检查父 cgroup 限额，资源不可见时不放行。退出码 2 表示资源受阻，0 仅代表资源准入；运行时依赖、资产、个人存储额度和 GPU 实际容量仍需资格验证。所有真实仿真、训练及重型回读都必须走同一个主机队列，排队或运行的源码保持不变，输出目录和 run_id 独立。

目前可行的后续方向是配置满足准入的主机，或单独实现并验证保留完整观测的有界内存记录路径，再重新资格验证。不要降低保护阈值来掩盖内存不足；不要把其他 Arena 任务的 24 环境偏好当作本 OpenArm recorder 的容量证据。不安装/升级仿真依赖、不覆盖历史输出、不上传报告或发布博客。
