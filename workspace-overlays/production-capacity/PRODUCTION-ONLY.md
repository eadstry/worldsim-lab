# 仅生产模式：按用户要求跳过实验后处理

用户要求取消 CPU 上的图像解压、独立数据校验与哈希计算。`produce.py` 是新增独立入口；原 `run.py`、`launch.py` 及生产覆盖层均不改写。仅新增此入口不改变原任务正在使用的源码。

本模式不调用 HDF5 读取、图像解压、全数据有限数/维度检查、每数组哈希、全文件SHA256、视频转码或反复读取图像。只读取已有的 JSON 运行结果、遥测计数、任务YAML和文件大小；监督器成功结束、固定尝试计数和导出关闭状态仍需符合配置。仿真内部原有成功判定、终态检查、控制频率和三路640×480/gzip2生产负载保持相同。

主指标改称“仿真终态接受并导出条数/最终文件就绪分钟”，不能称为独立校验后的合格数据吞吐，也不对未做的完整性、逐帧一致性作结论。旧批次已有的独立验收信息仅标为历史记录，本模式不重新验证。

## 切换与恢复

先暂停旧控制器，使其不再进入校验/转码；允许已运行的监督子进程完成当前批次并关闭文件。子进程完成后停止旧控制器，原文件保留。旧任务会显示被主动停止；这不代表已经成功落盘的批次仿真失败。

新任务在全新目录运行，`--reuse-run <原r02目录>` 复用其中已成功关闭的批次（含两个pilot和已有screen），不复制或重跑仿真。只接受相同生产工作区、匹配的环境数、导出设置、seed、固定尝试数、保持步数，以及完整的运行结果与遥测；原目录存在但未成功关闭时拒绝恢复，不静默补样本。数据验收和哈希已按用户要求豁免，因此文件内容身份与完整性没有再次验证。

总尝试预算仍最多74次，包括已执行部分；剩余筛选顺序及候选确认规则与原计划一致。候选基于仿真接受产出比较，不声称数据质量非劣。所有实际GPU运行仍使用同一个主机共享队列，禁止多组GPU性能对照相互争用资源。

`produce.py --help` 的路径参数与原入口相同，增加必需的 `--reuse-run`，不再使用 `--reuse-sync-pilot`。运行仍受70 GiB磁盘余量、8 GiB有效内存、44 GiB producer RSS及每批2400秒限制。已有依赖缺失则停止，不安装。

完成后用不额外压缩的 `.tar` 归档，因为HDF5本身已压缩；不再运行SHA256。归档仍需要一次磁盘读取但不做数据解码。收据明确哈希未计算。保留所有数据，夸克上传待目的目录与已认证入口，不误报完成。

轻量主机测试：`<现有autodata Python> -B -m unittest discover -s workspace-overlays/production-capacity -p test_production_only.py -v`。使用非HDF5的占位文件验证入口不会解码输出，覆盖错误计数、配置不一致、异步未关闭的拒绝。没有使用仿真或生成数据进行解压测试。
