LeRobot v3 与 OXE：两种数据抽象

OXE 是交换格式：它只统一外壳，把异构性推给下游；LeRobot v3 是存储格式：它统一了布局， 把一致性推给写入方。理解这一点，两类坑基本都可以提前预判 —— 一类是“字段含义对不上”，一类是“元数据与数据对不上”。

01

OXE 的三层结构

OXE

RLDS 只规定“数据集是 episode 的序列，episode 是 step 的序列”。shard 是物理文件、episode 是逻辑单元、step 是语义单元 —— 三层之间没有任何索引，要定位第 i 个 episode，只能顺着 shard 扫过去。这就是它天然适合流式训练、不适合随机访问的原因。

格式规范：RLDS（google-research/rlds）；字段命名来自 OXE 约定
02

LeRobot v3 的三处定位

LeRobot v3

v3 把这三层压成了“一张索引表 + 两种大文件”。一个 episode 在元数据里只有一行，这一行同时指向三处：parquet 的行区间、视频文件里的时间段、以及这两个文件各在哪个 chunk / 分片。读一帧 = 先查表，再定位分片，最后按行号或时间戳取。

真实 schema 取自 lerobot/pusht 与 lerobot/droid_1.0.1 的 meta/episodes
03

为什么 v3 要这么设计

取舍

v2.1 是“一个 episode 一组文件”，文件数与 episode 数线性增长；v3 改成“一组 episode 一个大文件”，文件数与数据量挂钩。代价很明确：在 v2 里读错文件最多是读错 episode；在 v3 里，元数据错了，读出来的是一个“看起来合法”的错误样本。

文件数按 10k episodes × 3 相机估算；“初始化快 3–5×”为官方口径
04

元数据说谎时，什么都不会发生

坑

这是 v3 与 v2 最大的行为差异，也是社区讨论最集中的地方：读取器信任元数据，不做反向校验。两个最小复现 —— 把 from_timestamp 偏移 1.5 秒、把 dataset_to_index 加大 3 —— 都能让读取器返回错误样本，而且文件哈希不变、加载无警告。

复现与结论来自 lerobot#4976；边界与 task 关联见 #4519；转换脚本见 #2401
05

OXE 的异构性是可以量化的

OXE

“OXE 很乱”不是感觉。按 OpenVLA 实际维护的 70 个数据集配置统计：只有 33 个带腕部视角、13 个有第二视角、5 个数据集完全没有 proprio，却被补成与 action 同形状的零向量。所谓标准化，就是 70 个函数把差异一个个抹平。

统计自 openvla/prismatic/vla/datasets/rlds/oxe/configs.py（70 个数据集）

转换链路上的六个断点

实践

把 OXE 转成 v3 时，异构性和索引一致性会叠在一起。这条链上每一步都有一个“不报错但结果错”的点，其中三个（fps、rollover、整帧偏移）只能在数据层面发现。
