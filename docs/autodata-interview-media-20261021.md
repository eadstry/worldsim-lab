## 新增场景与任务的来源

实际使用已存在本机的 `Yootta/World-SimReady-Home-mini`：`scene000430`，revision `f2c633749e7fdf3f981dfd1dd83fc253786713ac`。原始 USDZ SHA256 为 `d38ebd9e8312c46125bee1412c3a45933c245b890ea081c307fcfc4e37814ee6`。

Blender 直接导入原始 USDZ。整体平移 `(-22.35, 4.75, -0.75)` 米，把原餐桌表面放到 z=0。原餐桌 `mesh059` 的测量范围为 x=[-0.116691,1.234093]、y=[-0.453037,0.431028] 米，表面高度约为 0。新物理任务以该原生餐桌的包围盒建立支撑碰撞；其余家居几何用于渲染，未执行全屋碰撞或家具交互验证。

派生渲染停用天花板、餐桌椅与桌面装饰，保留住宅主要几何。Blender 显示材质与灯光是兼容用的替代配置，不表示原始 MDL 材质完全一致。源 USDZ、历史录像、上游源码与锁定提交均未修改。场景许可证沿用原数据的 CC-BY-NC-SA-4.0；包内不包含原始场景资产。

### 简化夹爪 RGB 排序

`physical_task.py` 使用 MuJoCo 3.8.0，三个平移自由度与双指平行夹爪。方块为 44 mm、50 g 的动态刚体；夹紧、抬起、搬运与释放依靠接触、摩擦和位置驱动，不对方块执行持续位姿写入，也不把方块焊接/绑定到手上。

颜色来自任务配置中的已知对象身份；这是按颜色目标执行的脚本任务，没有运行 RGB 图像识别、学习策略或 AutoData Mimic 扩增。三个初始布局 seed=7/19/31 各生成一条 19.8 秒轨迹。近景、全景和俯视分别展示这三个布局；因此拼版不是同一次仿真的同步三相机。

每条物理轨迹以 600 Hz 积分、30 Hz 记录。视频渲染每三个记录帧取一帧，即每秒 10 张不同渲染帧，再重复编码为 30 FPS H.264，未使用生成式插帧。适合 PPT 播放，但不应据 30 FPS 编码宣称物理观测采集为 30 张不同图像/秒。

### 官方 G1-D 下载与改装夹爪演示

官方来源：[Unitree Robotics 的 G1-D URDF](https://github.com/unitreerobotics/unitree_ros/blob/5994d4faef0a9cadd3287f8de0199a67eeb2a259/robots/g1_d_description/g1_d.urdf)。下载时固定到仓库 `unitreerobotics/unitree_ros` 的提交 `5994d4faef0a9cadd3287f8de0199a67eeb2a259`，机器人名 `G1_D`。URDF SHA256 为 `46527573a7140c7129c3587ba5591f269974deb893a0b095ebca500028b8bf40`，下载清单记录全部资源哈希。官方代码包许可证为 BSD-3-Clause。

官方 URDF 自带 `meshdir="meshes"`，同时网格文件名也带 `meshes/`。本地导入层消除重复目录并使用绝对网格目录；原文件保留不变。MuJoCo 导入后保留官方关节原点、轴、限位、惯量和被引用网格。

**原生 Dex3 灵巧手的本次五轮参数/控制尝试均未通过抓取验收。** 有一次早期尝试出现不稳定警告；后续加入转子惯量、调整阻尼与控制增益后可以稳定运行，但仍会推走物体或未能持续抬起。失败运行保存在本地，不列为成功素材。

成功素材采用 **官方 G1-D 机身与手臂 + 演示用平行夹爪改装**。原生右手的接触和显示被替换，新增两个有碰撞与位置驱动的滑动手指；这不是原装 Dex3 能力演示。移动底座固定，使用脚本 IK 和理想重力补偿；关闭机器人非手部与全屋碰撞，未验证导航、自碰撞规避、实机执行或策略泛化。

基座位姿为 `(0.42,-0.48,-0.60)` 米、yaw=π/2。官方右臂通过有界 IK 跟踪抓取阶段；新增夹爪夹起方块。先完成 11.1 秒的单方块任务，再完成 29.7 秒的完整 RGB 排序。完整任务初始 x 顺序为 G、B、R，最终按世界 +X 排列为 R、G、B。为形成成功示范保留固定布局；加入几毫米布局扰动的一次尝试未全通过，不能据当前视频声称随机布局鲁棒性。

## 实际验证

共享主机上的仿真、渲染和批量转码均通过 `scripts/task-queue.py` 提交。主要成功物理任务：165/166/167（简化夹爪三个布局）、191（G1-D 改装夹爪单方块）、197（G1-D 完整 RGB）。重要渲染任务：180/181/182、185、193、198/199/200，连接件显示精修为 203–206；转码和后处理为 201/207，原理动画为 202，选片与打包检查为 208/209。取消或失败尝试没有混入成功标签。

`verify_physics.py` 重新读取保存状态，检查有限数值、时间间隔、抬起持续帧数、最后一秒的位置与速度、松爪状态及夹爪撤离距离；G1-D 还检查具名夹爪/方块接触记录。该脚本是独立于生成器判定逻辑的状态复核，仍由同一执行代理编写，不属于独立审阅批准。

| 成功任务 | 复核结果 |
| --- | --- |
| 简化夹爪，3 个初始布局 | 每块在对应抬起/搬运阶段有 46 帧高于初始位置 12 cm；最终松爪、撤离、稳定归位；最终 RGB 顺序通过 |
| G1-D 改装夹爪，单方块 | 高于初始位置 12 cm 共 68 帧；最终目标 XY 误差约 3.7 mm；有 147 帧记录夹爪与方块接触 |
| G1-D 改装夹爪，RGB 排序 | 三块抬起约 0.169/0.171/0.170 m；最终目标 XY 误差约 3.7/0.4/8.9 mm；最后一秒稳定、松爪并撤离；最终顺序通过 |

完整视频重新解码检查与具体数量以交付 JSON 为准。原素材中一个 `openarm-overview-replay.mp4` 无法解码，已排除；v001 报告注明未同步的 10 张随机化渲染图也已剔除，保留 v002 有效图片。部分上游媒体文件只是约 130 字节的 Git LFS 指针，未作为可播放素材打包。

静态源码检查、主机检查、录像格式检查都不能替代物理任务验收；本次成功示范也不能替代泛化成功率测试。未发现可用的本地 3D Gaussian Splatting 场景，因此没有生成或宣称高斯背景视频。

## 实现与复现

实现位于 [workspace-overlays/autodata-interview-media](../workspace-overlays/autodata-interview-media/)。仅复用已有 Blender 5.1.2、MuJoCo、Python 与 FFmpeg，不安装/升级仿真依赖，不要求启动或修改 Isaac Sim/Arena 容器。新任务没有执行 AutoData 或 Arena 的包代码。

固定官方版本下载示例：

```bash
python3 workspace-overlays/autodata-interview-media/download_g1d.py \
  --revision 5994d4faef0a9cadd3287f8de0199a67eeb2a259 \
  --output runs/NEW/g1d-official
```

所有仿真/渲染命令按同一共享队列提交，并使用不存在的新输出目录。完整命令、版本、哈希和各步产物记录在 `simulation-evidence.json`；资源模型 ZIP 是原始官方资源，任务改装代码以 overlay 为准。源场景与 `.blend` 是本地运行资产，不随媒体包分发。
