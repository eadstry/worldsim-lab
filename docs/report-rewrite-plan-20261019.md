## 0. 一句话结论

这份 v001 的问题**不是信息不足，而是把内部验收标准直接当成了叙事结构**：它把"别过度解读"写成了主线，把方法与失败写成脚注，因此读起来像免责声明汇编而不是实验讲解。它的原始素材（底层 12 份报告）质量相当高，重写不需要新实验，只需要换一个组织原则：**一条问题链 + 每节一句可记住的结论 + 一张明确画出"哪些实验不可横比"的全景图**，并把 12 份底层报告的模板统一，让汇总可以机械地引用而不是靠作者记忆拼装。

### 1.4 结构与叙事层

- **9 节平铺 + 一节版本表 + 一节指标 + 一节计划**，没有递进关系。唯一承担递进的是第 13–21 行的 mermaid 路线图 A→B→…→H，而第 23 行立刻自我否定（"不能拿来当作同一个算法的前后 A/B"）——**图与正文互斥**。
- **两类不同性质的工作被塞进同一节**：§4 同时装 OpenArm 位姿随机化和 G1 视觉随机化；§5 同时装 cuRobo v2 升级评估（v1 vs v2）和 Franka IK vs cuRobo 避障（两种完全不同的对比）。读者在这两处跟丢。
- **跨任务数字并排制造了错误可比性**：1.30×（24 条，最终文件就绪）与 1.472×（8 条配对，同一口径）并列出现，即使写了免责声明，读者仍会横向比较。
- **"读图："句式失效**：出现 4 次，只有 1 次紧邻且对应其图；一次在 §2 图之前，一次（"读图要点"）后面根本没有图而是表格。6 张图中 3 张无任何读图或正文承接。而且读图句只是把紧随其后的表格数字重述一遍（L33 与 L35–39 完全重复），把图降格成配图。
- **指标悬空**：§8 定义了"严格合格吞吐 = 物理终态与完整性同时通过的轨迹数 ÷ 最终文件就绪时间"，但**前 8 节没有任何一个实验报出过这个指标**。

### 1.6 交付层（对外形态）

- **站点当前打不开**：`https://embodied-experiment-atlas.jiaxuan-li996.chatgpt.site/` 从本机用浏览器 UA 与 curl 两种方式请求均返回 **Cloudflare 403**（"Sorry, you have been blocked"），`/report.md` 同样 403。若目标读者在国内，这个发布等于没发布——需要换托管或加可访问的镜像（项目已有 `private-blog` 构建链可用）。
- **包不自包含**：4 个关键引用跳出仓库指向兄弟 worktree（`../../../../g1-home-domain-20261017/…`、`…/franka-curobo-comparison-20261017/…`、`…/banana-wrist-force-20261017/…`），这些 worktree 一旦归档或清理，证据链即断。发布站点时它们被 `build_page.py` 替换成不可点击的灰字（`local-reference`），**对外读者因此看不到任何一手证据**。
- **站点生成器有隐患**：`build_page.py` 把路线图**硬编码**成 `FLOW` 列表，忽略 `report.md` 里 mermaid 的真实内容——正文改了路线图，页面会静默不一致。

### 1.7 根因：12 份底层报告模板失控

汇总之所以只能"重排 + 免责"，是因为底层报告没有统一骨架，无法机械聚合。实测：

- **结论位置四种**：置前（3 份 cuRobo）/ 中置（效率复盘 v003 第 163 行，结果先讲）/ 尾置（shared-config v003"版本及结论边界"）/ 根本没有标题（internal-timing、domain-randomization、openarm-benchmark）。
- **同级要素有 6–7 种命名**：结论类 6 种、边界类 7 种（"证据边界与本地交付"/"计时完整性和范围"/"版本及结论边界"/"复用边界"…）、证据类 7 种、决策类 6 种。
- **元信息缺失严重**：版本号 3/12 缺（internal-timing、benchmark），日期 2/12 缺，作者/任务来源 **0/12**，可被汇总引用的一句话摘要块 **0/12**，复现命令只有 2/12，与前版差异只有 1/12。`domain-randomization/v001、v002` **零章节、无锚点**，汇总想引用某一节都做不到。
- **数字口径不统一**：计时就有 6 个名字且不同义（墙钟延迟 / 互斥和 / 最终文件就绪 / 整批收尾 / 主循环独占 / execute 累计）；表列 `v1|v2` 与 `改进前|改进后` 混用。
- **脱敏不彻底**：`internal-timing` L153–155、`domain-randomization` L37 仍含绝对路径与 conda 解释器路径。

结论：**不统一底层模板，汇总报告每写一版都要重新踩一遍同样的坑。**

## 3. 统一底层模板（v2）

放 `docs/report-template.md`，所有 `outputs/<artifact-id>/vNNN/report.md` 遵守。

**① 元信息块（表格，机器可读，必填）**
`experiment_id`｜`version`｜`date`（ISO+时区）｜`status`（passed / failed / partial）｜`一句话结论`｜`三个关键指标`｜`上游 commit`（AutoData / cuRobo / Arena 逐个）｜`环境`（Python / Torch / Isaac Sim / GPU / 驱动）｜`样本量`｜`交付范围`｜`需求来源`

**② 结论与决策（≤200 字，三段式）** 观察到什么 → 意味着什么 → 建议动作；必答"能支持哪个决定、不能支持哪个决定"。

**③ 问题与假设** 本实验要证实/证伪什么。

**④ 方法与配置** 必答基线是什么、参数如何对齐；含差异表与"非等价/非等计算量"声明。

**⑤ 结果** 表列固定为 `指标 | 基线 | 改动 | 差值 | 相对变化 | n | 口径引用`。

**⑥ 成功判据与正反例** 判据先写，再给通过实例与不通过实例。

**⑦ 测量口径** 起点、终点、是否含 GPU 同步、单位、各项可否相加。

**⑧ 适用范围与不得外推** 明确列出未覆盖对象。

**⑨ 证据与复现** 相对路径清单 + 可执行命令 + 产物哈希。

**⑩ 版本关系与后续** 与前版差异、被推翻的旧结论、未完成项。

**图表规范**：`figures/NN-slug.png`（配同源 SVG）；图注必须含 n、口径、数据来源文件；不截断坐标轴；单轮数据不画置信区间；正文数字必须与 `data.json` 一一对应；**图题即结论**（取消"读图："标签）。

**禁止出现（硬规则，写进检查脚本）**：`/Users/…`、`/home/…`、`.worktrees/` 及 worktree 名、原始 `runs/<机器目录>`、队列/任务号、conda 绝对解释器路径、主机名、`../..` 跨 worktree 引用、"未上传飞书/ChatGPT"这类交付过程语（移入 manifest）。

**范本**（直接固化其做法，不要另创）：
- `curobo-v2-openarm-mvp/v001`——结论三段式含 Wilson 区间；"测试条件与配对检查"主动排除伪结论；配置齐平表；用"535 个受保护文件 SHA-256 不变"证明未污染环境。
- `autodata-arena-shared-config/v003`——63 行最紧凑；"成功判据正反例"独立成节；证据清单逐文件说明用途；已把机器根路径替换为占位符。
- `autodata-v1-internal-timing/v001`——计时口径最严（互斥和与墙钟闭合误差 <10 µs、声明钩子开销、OOM 试跑排除）；其唯一缺陷恰是缺元信息头。
