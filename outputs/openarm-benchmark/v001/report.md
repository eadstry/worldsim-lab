# OpenArm 无训练策略评测示例

当前 OpenArm 左臂抓放配置可以用于搭建 Arena benchmark 示例。这个版本提供可执行协议、
运行编排、计分检查和当前 Arena 的任务接口转换，不需要训练好的策略。
本次交付为用户指定的本地交付，飞书和 ChatGPT 上传均未执行。

## 示例如何工作

| 项目 | 控制来源与初态 | 回合预算 | 验收目标 |
| --- | --- | --- | --- |
| smoke | 零动作，源配置随机 reset，2 个并行环境 | 至少 2 回合，每回合 0.5 秒 | 记录失败回合和原生报告；零成功也应通过该负例检查 |
| regression | 交付夹具动作和固定初态，1 个环境 | 1 回合，90 秒 | 原成功判据下完成抓放 |
| baseline | 零动作，随机 reset，4 个环境，种子 11/22/33 | 每种子至少 8 回合，每回合 90 秒 | 可选的完整预算无动作基线 |

默认只执行 smoke 和 regression。固定回放检验环境及控制链路，不能估计模型在随机场景下的能力。
协议的成功率分母为实际完成回合数，保留所有失败；未完成目标导致执行检查失败。

## 复用边界

场景、左臂控制器、三路相机和标定、机器人、reset 与成功判据复用原 OpenArm 交付包。
当前生产 runtime 的 9 份关键定义与原交付相同。生成用 SkillGen 的选源、规划器、
成功演示配额和导出进程不进入本例评测。源 OpenArm 配置为 30 秒；评测沿用交付的 90 秒预算。

Arena `9886659` 要求 `TaskTerminationCfg`，原交付 `8b82dca` 使用 Isaac Lab 的结束项。
新 overlay 在当前接口上用一个 `ProgressObjective` 包装原放置判据，保留原掉落判据和显式超时。
这项转换通过主机替身测试，仍需真实 GPU 环境复验。

## 使用交付包

`code/` 是可移交代码快照。它依赖另行提供的完整原始包
`openarm_pick_place_arena_20261013_120511`，不包含其机器人资产、源数据集或策略权重。
从本封装目录执行下面的命令，路径由机器本地环境变量提供：

```bash
python3 code/run.py \
  --bundle "$OPENARM_BUNDLE_ROOT" \
  --arena-root "$ARENA_ROOT" \
  --runtime-python "$ARENA_PYTHON" \
  --output-dir /path/to/new/openarm-demo-001 \
  --dry-run
```

三个变量分别指向原交付包、明确选择的 Arena 源码根目录和已经配置好的仿真 Python。
预演不启动仿真、不写结果目录。GPU 环境就绪后去掉 `--dry-run` 执行。
详细契约、结果文件和复验方法见 [代码说明](code/README.md)。
仓库中的维护入口为 `workspace-overlays/openarm-benchmark/`；封装版本发布后保持不变。

## 以后接入学习策略

保持同样场景、reset 分布、成功阈值和时间预算，另外接入符合 `[B,7]` 相对 TCP IK
输出的模型适配器。必须明确图像预处理、动作反归一化及限幅、历史状态清理。
学习策略在独立随机初态上的测试应形成新的协议版本，不能混入固定回放回归成绩。
