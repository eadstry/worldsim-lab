关键：真正的“随机化”只有三处 —— ① 边界抖动、② 源段选择、⑤ 动作噪声（外加双臂的④协调噪声）。 其余步骤在有采样结果后都是确定性的。

①.5 STEP 0 展开：环境 Reset 的随机化（输入 → 重抽 → 落盘）

环境层的随机化不是 AutoData 写的，是基任务（isaaclab_tasks）自带的 Isaac Lab EventManager 事件项；AutoData 只在开跑前用 env profile 做增删改，然后每个 attempt 的 env.reset() 里重新抽一次。

输入 · 开跑前只发生一次

规则从哪来
  • 基任务 events（Isaac Lab 代码）： randomize_cube_positions、randomize_franka_joint_state
  • env profile YAML（--env_profile）： events.remove / add / override
  • apply_env_profile() isaaclab_env_interface.py:116 把它们写进 env_cfg.events
  • 此时还没有任何随机数，只是把“规则”装好
→

执行 · 每个 attempt 重抽

规则怎么跑
  • _reset_environment_for_generation() data_generator.py:617
  • env_loop 里 env.reset(env_ids) isaaclab_env_interface.py:259
  • → EventManager 执行 mode="reset" 事件，逐条抽签
  • → 再进入生成层的边界抖动 / 选源段 / 动作噪声
→

输出 · 落盘的是“结果”

抽到的状态怎么存
  • get_scene_state() data_generator.py:628 → GenerationResult.initial_state
  • 每个 demo 的 initial_state 写进输出 HDF5
  • --result_file JSON：记录 {algorithm, stats, profile name/path/planner}
  • 规则本身不落盘；seed 让重抽过程可复现

一句话：规则是输入（基任务 events ＋ profile delta，在代码和 YAML 里）；随机化在每个 attempt 的 env.reset() 里按规则重抽一次；AutoData 只保存抽到的状态（每个 demo 的 initial_state） 和复现元信息（result_file ＋ seed）。profile 不是 AutoData 固化的随机化配置。

② 子任务边界抖动（randomize_subtask_boundaries）

源演示里每个子任务只有枯燥的一组分界点。生成时按配置的范围把分界点“抖动”，于是同一个源段能落在不同时间窗口里。

加载数据集时，`DataGenInfoPool` 会用最坏情况（所有偏移取极值）预演一遍，断言“子任务非空且不重叠”，标注错的源数据会立刻报错。

③ 源演示段选择（selection_strategy）

同一子任务，在源数据集里有很多段候选。先算「当前场景」与每个候选段起点位姿的距离 d、升序排序， 取前 k（nn_k），再在这 k 个里等概率随机挑 1 个（候选不足 k 个时退化为全池随机）。

策略由每个子任务的 selection_strategy 指定： random（全池随机）、nearest_neighbor_object（按物体位姿）、nearest_neighbor_robot_distance（按 EEF 位姿）。
重选粒度：select_src_per_subtask（每段重选）/ select_src_per_arm（每条臂各选）。

④ 动作噪声（action_noise）

轨迹本身是确定的，但每一步发给机器人的动作会加一个高斯扰动：位置增量和旋转增量都被扰动。这是让“同一条源段”产生不同执行细节的关键。

apply_noise_during_interpolation 决定桥接插值阶段是否也加噪。 单臂（single_arm_embodiment_adapter）与双臂（bimanual_embodiment_adapter）都作用于 pose 部分，夹爪等 passthrough 通道不加噪。

⑤（仅双臂）协调噪声

DexMimicGen 的 COORDINATION 约束会算出一个 delta 位姿把两条臂对齐；这个 delta 可以叠加均匀噪声，让双手的相对位姿也有差异。

一句话：场景多样性来自 Reset（环境层），轨迹多样性来自生成层 —— 边界抖动改变“时间段”，源段选择改变“用哪段”，动作噪声改变“怎么执行”。三者叠加，就得到大量彼此不同的演示。
